# Раунд A готов: каркас настроек собран, уровень 0 и уровень 1 зелёные

## Коротко

- **Каркас интерфейса настроек 0.5.0 собран и проверен.** На странице RVN → «Сравнение» появилась первая вкладка «General» с React-приложением на компонентах WordPress. Пока это заглушка без сохранения: уведомление + две строки текущих настроек. Так и задумано — функции придут в раундах B–E.
- **Проверка:** уровень 0 — 5/5, уровень 1 — 12/12 (админка теперь 13/13 с новой проверкой монтирования React, Plugin Check 0/0). Регрессий ноль.
- **Бандл весит 1,4 КБ** — React берётся из ядра WordPress, а не из плагина. `node_modules` в рабочую область не попал: сборка идёт во временной папке.
- **Версию в заголовках не поднимал** — специально: 0.5.0 ещё не готова, и папка с надписью «0.5.0» вводила бы в заблуждение. Подъём — в раунде F, как договаривались. В журнале изменений есть раздел «0.5.0 (in development)».
- Код витрины не тронут: кнопки, счётчики, таблица, уведомления — всё как было.

## 1. Что именно сделано

**Новые файлы:**
- `wp-dev/admin-ui/` — исходники (`package.json`, `src/index.js`), скрипт сборки `build.sh`, инструкция `README.md`.
- `includes/admin/class-settings-app.php` — PHP-bootstrap: подключает бандл только на вкладке «General», передаёт nonce, настройки и переведённые строки, выводит контейнер и заглушку на случай сбоя JS.
- `assets/admin/` — собранный `settings.js`, `settings.asset.php` с зависимостями и версией, защитный `index.php`.

**Изменения:**
- Вкладка «General» — первая и по умолчанию; остальные вкладки не тронуты.
- 8 новых строк переведены (шаблон вырос со 178 до 186 записей).
- Тест админки обновлён: ждёт 4 вкладки и проверяет, что React-приложение смонтировалось.
- Сгенерированный `settings.asset.php` исключён из проверки имён файлов (имя с точкой — требование WordPress, исходники ревьюятся в `wp-dev/admin-ui/src/`).

**Как устроена сборка:** `bash wp-dev/admin-ui/build.sh` копирует исходники во временную папку, ставит пакеты там же, собирает через `wp-scripts build` и кладёт два файла в плагин. Повторяемо, документировано, область не раздувается.

## 2. Проверка и одна несерьёзная история

Сначала уровень 0 нашёл 4 замечания — все в сгенерированном файле (см. выше), исправлено исключением, повтор зелёный.

Затем уровень 1: 11/12 — упала проверка витрины «кнопка стала активной». Разбор показал, что это гонка в самом тесте, а не регрессия: товар добавился (список `[26]`), уведомление с текстом появилось, счётчик обновился — просто две проверки сработали раньше, чем долетел ответ сервера. Мой код витрину не трогает вообще. Одиночный перезапуск — 17/17, полный повтор уровня 1 — 12/12. Красные промежуточные артефакты удалил, зелёные лежат в `docs/test-reports/0.5.0/runs/`.

Все подробности — в `docs/test-reports/0.5.0.md`, там же таблица прогресса 0.5.0.

## 3. Мини-проверка для вас (3 пункта, ~3 мин)

Поставьте папку плагина на тестовый сайт как обычно:

- **A1)** RVN → «Сравнение» открывается, первая вкладка — «General»: видно уведомление про 0.5.0 и таблицу из двух строк (лимиты 50 и 12).
- **A2)** Остальные вкладки (Page / Comparison fields / System status) работают как раньше, таблица состояния показывает 5 строк.
- **A3)** Витрина не изменилась: кнопки, счётчик, таблица, уведомления — как было.

Отвечать можно так: «A1) Ок», «A2) Ок», «A3) Баг + скриншот».
Полный регрессионный чек-лист из 23 пунктов прогоним один раз в конце 0.5.0, а не после каждого слайса.

## 4. Чек-лист для ответа

1) Дальше — раунд B (вкладка «Основное»)? [по умолчанию: ждём]
- «1) Да, раунд B» / «1) Ждём»

## Следующий шаг

Если скажете «да» — начну раунд B: вкладка «Основное» (лимиты, правила, категории, исключения с поиском, где показывать кнопку, повторный клик, цвет, отступы, «Сбросить всё»), каждый слайс с уровнем 0, уровень 1 в конце раунда. Если хотите сначала прогнать мини-проверку A1–A3 — жду её результатов, раунд B начнём после.
