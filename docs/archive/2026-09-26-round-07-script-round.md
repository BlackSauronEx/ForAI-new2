## 1. Что изменилось в `stand.sh`

| Новшество | Зачем |
| --- | --- |
| **`doctor`** | Проверяет OS, sudo, apt, коднейм дистрибутива, сеть до sury и wordpress.org, RAM, диск, init-систему. Вердикт: «полный стенд возможен / возможен с замечаниями / невозможен» — вместо смерти на первой строке в чужой среде. Переменная `DOCTOR_MIN_RAM_MB` позволяет снизить порог фильтра памяти, если среда нестандартна. |
| **`install --php=8.1,8.3 --browsers=chromium`** | Минимум по умолчанию (ваше решение из аудита). `none`/`chromium`/`webkit`/`firefox` — по списку; `all` ставит 4 версии PHP. Вместо «всё и сразу». |
| **Авторазрешение версий `min`** | `--name=min` без явных версий берёт **свежайшую патч-версию бранча** WP 6.6.x и WC 9.0.x через официальные API. Жёсткие номера не зашиты; точные версии можно подавить флагами `--wp=6.6.4 --wc=9.0.8` для воспроизводимости. |
| **Старт MariaDB без привязки к init** | `service mariadb` (systemd), `mysqld_safe` (без systemd) — что найдётся. |
| **Проверка хранилища перед работой** | Ловит битые просыпания песочницы: если системные таблицы MariaDB не читаются, скрипт останавливается уже на старте с внятным сообщением, а не рушится посреди создания базы. |
| **`down --name=all` и `stop`** | `stop` гасит все веб-серверы и MariaDB и **доказывает** это пустым `pgrep -a -f 'mysqld|php -S'`. Правило «конец раунда — в покое» стало исполняемым, а не декларативным. |
| **env-файлы стендов** | `stand.sh up` пишет `/tmp/wp-stand-<имя>.env` (PHP, порт, версии WP/WC). `check.sh` читает порты оттуда — хардкода 8080/8081 больше нет. |

## 2. Что изменилось в `check.sh`

| Новшество | Зачем |
| --- | --- |
| **Уровни `level0/level1/level2`** | Ровно как договорились: статика после каждого изменения; сборка на `main` перед выдачей; полная матрица перед релизом. Одна команда на раунд. |
| **`--browser=chromium|webkit|firefox`** | Сквозной параметр до Playwright-скриптов через `NODE_BROWSER`. Дефолт — Chromium. |
| **Порты из env-файлов** | `check.sh <режим> min` сам узнаёт порт стенда, а не гадает. |
| **Архивация прогонов** | Каждый прогон копируется из `/tmp/rvn-check/` в `docs/test-reports/<версия>/runs/<режим>-<дата>/`. Сброс песочницы больше не уничтожает доказательства: они лежат в рабочей области. |
| **Лимит памяти PHPStan 1500M** | Было `2G` — на среде с 1.9 ГБ RAM это падало бы гарантированно. |
| **Легаси-режимы сохранены** | `tests|stand|front|table|cache|pcp`, а также `runtime` и `all` работают как раньше — старые привычки ничего не ломают. |

## 3. `docs-check.sh` — что сверяет (14 пунктов)

1. Версия в трёх местах: заголовок плагина = `RVN_COMPARE_VERSION` = `Stable tag` (сейчас 0.4.1).
2. Версия фигурирует в `STATUS.md`.
3. Есть запись в `CHANGELOG.md`.
4. Правило «без привязок к фреймворку»: сканирует только правообразующие файлы (`AGENTS.md`, `README.md`, правила в `docs/`); упоминания-запреты не считаются нарушением.
5. ZIP-артефактов в рабочей области нет.
6–12. Обязательные файлы на месте (`AGENTS.md`, `README.md`, `STATUS/HANDOFF/LOG/ANSWER/CHECKLIST`, скрипты).
13. Скрипты стенда на месте.
14. Чистота префикса: сканируются PHP-файлы без `languages/` (имя автора Revolen в переводах — законно и не нарушение).

Два первых прогона скрипта дали ложные срабатывания ровно в местах, где проверки были написаны слишком широко — я их сузил по фактам и поставил объяснение в комментарии скрипта, чтобы следующие сессии не тратили циклы.
