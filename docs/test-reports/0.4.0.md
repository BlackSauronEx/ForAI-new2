## Найдено и исправлено

### 1. Дефект: статический шорткод раскалывал товары по вкладкам категорий

**Как проявился:** `check.sh table main` — «Статический shortcode показывает две
колонки (1 колонок)». Страница с `[rvn-compare-table products="26,11"]` показывала
одну колонку вместо двух.

**Причина:** `Table_Data::build()` всегда строил вкладки через
`Category_Model::tabs_for()`. Товары 26 и 11 лежат в разных категориях, поэтому
таблица разбивалась на две вкладки по одной колонке — посетитель видел по одному
товару за раз, хотя админ перечислил конкретные ID и ждал их бок о бок.

**Исправление:** у `Table_Data::build()` появился третий параметр
`bool $single_tab`; REST `GET /table` передаёт `true`, когда запрос содержит
`products` (то есть пришёл от статического шорткода). В этом режиме `build()`
локально выставляет `compare_rule = 'all'` — все запрошенные товары идут одной
группой «Все товары». Новых строк для перевода не потребовалось (метка уже
существует), i18n остался полным.

**Проверено после правки:** `table main` 7/7, `table min` 7/7, повторный
статический прогон зелёный.

### 2. Устаревшее ожидание теста: таблица состояния в админке

**Как проявился:** `check.sh stand main` — «Браузер: меню RVN — Таблица состояния
системы (0 строк)».

**Причина:** тест `wp-dev/e2e/admin-smoke.cjs` открывал страницу «Сравнение» и
сразу искал таблицу состояния. В итерации 3 страница разбита на вкладки
(Page / Comparison fields / System status, по умолчанию первая), поэтому таблица
переехала в третью вкладку. Это **не дефект плагина**, а устаревшее ожидание теста:
он был написан до появления вкладок и ни разу не запускался.

**Исправление:** тест теперь проверяет наличие трёх вкладок и переходит во вкладку
System status по ссылке. Покрытие выросло: `stand main/min` — 12/12.

### 3. Добавлены регрессионные тесты доступности товаров (задача A)

Первичный аудит утверждал, что недоступные товары не отсеиваются. Проверка кода
показала обратное: правило живёт в `Compare_Service::product_available()` и
применяется и к списку, и к данным таблицы. Чтобы это не осталось «на словах»,
в `wp-dev/tests/core-logic.php` добавлено 5 проверок (было 36 → стало 41):

- приватный товар недоступен;
- товар в корзине (trash) недоступен;
- несуществующий товар недоступен (было раньше);
- состояние гостя: черновик, приватный и корзина отсеяны из списка;
- таблица: недоступные товары не попадают в колонки.

### 4. Форматирование по WPCS

`phpcbf --standard=wp-dev/phpcs.xml.dist` поправил выравнивание в
`class-assets.php` и `class-table-data.php`; вручную устранены Yoda-ошибка в
`class-shortcodes.php` (сравнение вынесено в переменную `$is_static`) и
предупреждение о зарезервированном слове `static` в имени параметра
`Table_View::render()` (переименован в `$is_static`).
